## Черновик A — для CTO-аудитории

**Название вакансии (37 символов):**
```
Технический лид автономной разработки
```

**Описание вакансии:**
```
Работаем над открытым MIT-проектом UNTIL: цикл «цель → исследование → приоритет и ТЗ → реализация → независимая приёмка → release candidate → наблюдение результата» идёт без ручного согласования задач.

Исполнитель не только пишет код: критерий приёмки — собственный тест проекта. Упал тест — агент читает ошибку и чинит, пока тест не станет зелёным. Правки ограничены allowlist'ом, провал откатывается байт в байт.

Проект открыт и проверяем: 82 детерминированных теста (exitCode 0), публичный CI, SBOM, пакет доказательств и документ по безопасности. Домен проекта — balanov.pro; ссылки на репозиторий, CI и доказательства — на странице работодателя и в «Контактные данные».

Роль — технический лид этого цикла: архитектура ролей, независимая приёмка, безопасность автономного исполнения.
```

**Обязанности:**
```
— Проектировать расширения детерминированного ядра: роли, acceptance-проверки, leases, идемпотентность, работа с любым OpenAI-совместимым endpoint, включая локальные модели.
— Усиливать независимую приёмку и evidence gate: синтетический сигнал не должен открывать delivery; поддерживать epoch fencing и hash-chained журнал аудита.
— Держать зелёными 82 теста и расширять их; публичный CI обязателен.
— Вести модель угроз и границы применения: песочница, секреты, внешние эффекты, риск-контракты.
```

**Требования:**
```
— Опыт backend или системной разработки на Node.js 24+ либо на сопоставимом стеке; понимание идемпотентности, WAL, leases и восстановления после сбоя.
— Опыт интеграции с LLM-сервисами и умение отделять детерминированное ядро от модели.
— Умение писать тесты на отказ (fail-closed), а не только на успешный сценарий.
— Готовность вести открытый код: всё, что попадает в репозиторий, читается сторонним наблюдателем.
```

**Условия:**
```
— Удалённая работа, РФ, гибкий график.
— Открытый MIT-код, публичный CI, опубликованные доказательства.
— Границы честно: UNTIL — не OS-песочница и не замена команде; MVP 0.3.0.
— Оплата: [впишите фактическую сумму или диапазон].
```

## Черновик B — для CEO-аудитории (основатели, владельцы)

**Название вакансии (46 символов):**
```
Руководитель направления автономной разработки
```

**Описание вакансии:**
```
Открытый MIT-проект UNTIL закрывает разрыв между «поставил задачу» и «получил проверенный результат». Задача формулируется как бизнес-цель с метрикой, бюджетом и допустимым риском; далее цикл идёт сам: сигналы → приоритет → ТЗ → реализация → независимая приёмка другой ролью → release candidate с фиксированным hash → наблюдение результата и запуск следующей работы.

Проверяемость встроена: 82 детерминированных теста в опубликованном proof-бандле (exitCode 0), CI публичный, синтетический сигнал не открывает поставку, поздние результаты отклоняются, журнал аудита хеш-цепочкой. Модель может работать на вашей инфраструктуре через Ollama или LM Studio — данные не покидают контур. Домен проекта — balanov.pro; ссылки — на странице работодателя и в «Контактные данные».

Роль — взять на себя продуктовую линию и перевести её работу в этот цикл.
```

**Обязанности:**
```
— Сформулировать бизнес-цели, метрики и бюджеты риска, закрываемые автономным циклом, и отвечать за результат.
— Приоритизировать: одна цель за раз, без параллельного «всё сразу».
— Фиксировать критерии приёмки до реализации: что считается готовым, решаете вы.
— Разбирать результаты наблюдения и формулировать следующую работу, а не «ещё задачу».
```

**Требования:**
```
— Опыт руководства продуктовой линией: от цели до измеримого результата, а не от задач до задач.
— Способность описать бизнес-результат в наблюдаемых метриках, а не в задачах.
— Готовность работать с системой, где часть решений принимает код, и отвечать за границы её полномочий.
— Ответственность за честность: «не сделано» — валидный результат, который нужно уметь произнести.
```

**Условия:**
```
— Удалённая работа, РФ, гибкий график.
— Открытый MIT-код и опубликованные доказательства: любой может проверить.
— Границы указаны прямо: UNTIL не заменяет команду и не делает production-деплой; статус — engineering MVP 0.3.0.
— Оплата: [впишите фактическую сумму или диапазон].
```

## Черновик C — для продакт-лидов

**Название вакансии (38 символов):**
```
Продакт-менеджер автономной разработки
```

**Описание вакансии:**
```
Открытый MIT-проект UNTIL устроен так, что работа продвигается без ручной координации: незакрытая цель создаёт следующую ограниченную задачу с заранее зафиксированными критериями приёмки; реализацию ведёт одна роль, проверяет другая, независимая; принятые файлы собираются в локальный release candidate с content hash; наблюдение после выпуска либо закрывает результат, либо создаёт следующую работу.

Продакт-менеджер здесь не «задаёт задачи и перекладывает». Его роль — связать сигналы (интервью, инциденты, продуктовые данные) с возможностью, которую команда действительно может поддержать, и превратить это в критерии, по которым приёмка однозначна. Конструкция проверяема: 82 детерминированных теста в опубликованном proof-бандле (exitCode 0), CI публичный, синтетический сигнал не открывает поставку. Домен проекта — balanov.pro; ссылки — на странице работодателя и в «Контактные данные».
```

**Обязанности:**
```
— Вести путь от сигнала к цели: интервью, инциденты и продуктовые данные связывать с тем, что команда может поддержать.
— Формулировать критерии приёмки, проверяемые автоматически, до начала реализации.
— Приоритизировать одну цель за раз и отвечать за обоснованность выбора.
— Разбирать, почему цикл не закрылся, и менять цель или критерии — но не доказательства.
```

**Требования:**
```
— Опыт продуктового менеджмента: сигналы, приоритизация, критерии готовности.
— Умение написать критерий приёмки так, чтобы его можно было проверить тестом, а не «посмотреть глазами».
— Опыт работы с технической командой без требования писать код.
— Внимание к деталям: «почти» и «не воспроизводится» — это разные результаты.
```

**Условия:**
```
— Удалённая работа, РФ, гибкий график.
— Открытый MIT-код, публичный CI, опубликованные доказательства.
— Границы указаны прямо: MVP 0.2.0, не OS-песочница, не замена команде.
— Оплата: [впишите фактическую сумму или диапазон].
```

## Как публиковать и распространять — легально

**Поля в ЛК hh.ru.** «Название» — только должность. «Описание» — блок «Описание вакансии» + «Обязанности» + «Требования» + «Условия». «Контактные данные» — сюда, а не в описание: полные ссылки на репозиторий, CI, пакет доказательств (`until-proof.zip`), документ по безопасности и страницу проекта. Страница работодателя — место, где живёт ваш employer brand: там баннер, описание проекта и все ссылки. Домен в описании — только `balanov.pro`, без `https://` и без пути.

**Распространение — только встроенными средствами площадки** (иначе вы нарушаете закон о рекламе, а не только правила hh.ru):
1. «Е-mail рассылка вакансии» — рассылка соискателям, выразившим согласие; текст шаблонный, предоставляется hh.ru, ссылка ведёт на вашу вакансию (п. 3.68 Условий оказания услуг).
2. «Рассылка вакансии по СМС» — для узких таргетингов.
3. Clickme — интернет-реклама вакансии на площадках Яндекса, VK и самом hh.ru.
4. «Вакансия дня» / «ТУРБО ОТКЛИК», брендирование страницы работодателя.
5. «Выборки резюме» — до 1200 подходящих резюме, контакты на 7 дней: 4 428 ₽ (Москва, СПб и области), 3 025 ₽ (остальные регионы РФ и СНГ) — https://hh.ru/article/selection
6. Лендинг Talantix: из вакансии делается отдельная страница с уникальной ссылкой, которую можно транслировать любым законным способом; лендинг бесплатен в тарифе «Оптимальный» — https://feedback.hh.ru/talantix/knowledge-base/article/landing

**Чего делать нельзя.** Не рассылать ссылку на вакансию по списку компаний, собранному из hh/2GIS/парсеров. Не использовать бота, расширения или скрипты для массовой работы с резюме — hh.ru блокировал за это аккаунты работодателей. Не дублировать одну вакансию ради охвата: дубль — нарушение правил размещения, а повторная публикация из архива считается новой публикацией.

## Чек-лист перед нажатием «Опубликовать»

1. Позиция реально открыта, у неё есть бюджет и человек, который будет её закрывать.
2. В описании нет ни одного рекламного призыва («попробуйте», «купите», «внедрите», «замените команду»). Только описание работы и проверяемые факты.
3. Название — только должность, без слоганов, зарплаты и формата.
4. Есть все четыре блока: описание, обязанности, требования, условия.
5. Указан домен `balanov.pro` без протокола и пути; полные ссылки — на странице работодателя и в «Контактные данные».
6. В описании нет контактов (телефон, e-mail, Telegram).
7. Зарплата вписана честно — либо конкретная сумма/диапазон, либо явное «по договорённости»; пустых плейсхолдеров в публикации быть не должно.
8. Границы указаны прямо: MVP 0.2.0, не OS-песочница, не production-деплой.
9. Числа в тексте совпадают с текущим состоянием репозитория: прогоните `npm test` перед публикацией и поставьте фактический зелёный результат с датой (проект активно дорабатывается, число тестов меняется). Ссылки на CI, proof-бандл и security-документ живы.
10. Спросите модератора-человека: не является ли описание «информационной, из которой невозможно получить содержательной информации» и нет ли в нём признаков рекламы (п. 6.1.20). Если отклонили — не перепубликуйте тот же текст под другим именем: повторная публикация одной и той же вакансии запрещена.
