# Security policy

## Reporting a vulnerability

Report vulnerabilities privately through [GitHub Security Advisories](https://github.com/Balanov/until/security/advisories/new). Include the affected version, a minimal reproduction, impact and a safe contact channel. Do not include real credentials, customer data or exploit payloads against third-party systems.

## Trust boundaries

UNTIL treats model output, external documents, repository content, skills, tool results, remote cards and connector payloads as **untrusted data**. Role text is not authorization. The deterministic kernel owns tasks, capabilities, budgets, verdicts and side effects.

- Unknown task kinds, check types and outbox actions fail closed.
- Builders cannot verify their own artifacts or publish them.
- Only a different verifier role can create a verdict.
- Release requires both an independent passing verdict and the evidence gate.
- Synthetic or inferred signals cannot unlock delivery.
- High-risk contracts stop with `blocked_risk` unless a separate risk boundary is implemented.
- Stop uses a persistent epoch; late results are rejected before dependent work or release.
- External actions use stable idempotency keys and a durable outbox.

## Execution warning

**UNTIL is not an OS sandbox.** The built-in artifact executor is intentionally narrow, but an external builder or command profile is a process with the operating-system user's permissions. File checks constrain artifact paths and real symlinks, but they do not contain a malicious process.

Run external builders only in a disposable OS, VM or container sandbox with:

- no inherited secrets;
- a dedicated low-privilege identity;
- read-only base inputs and a separate writable output volume;
- explicit network egress rules;
- CPU, memory, process, output and wall-time limits;
- tracked process trees and a tested kill switch.

`sandboxConfirmed: true` is an explicit administrator assertion, not a sandbox implementation. Do not set it for an unisolated process.

## Command profiles

Acceptance command profiles are registered by the operator, never generated by a model. They use argv arrays without shell interpolation, bounded output, timeouts, an environment allowlist and realpath checks for artifacts and working directories. Exit code 0 alone is insufficient: a profile must produce the declared output expectation.

## Secrets and data

API keys are read only from environment variables named in configuration. Do not put keys in `until.config.json`, goals, signals, artifacts, issues or proof bundles. Review all traces before sharing them: source content can contain personal data, proprietary code or credentials even without an explicit secret field.

SQLite and JSON proof files are not encrypted. Apply OS disk permissions, retention and backup policies appropriate to the source data. Use real-participant consent and purpose limitation for customer research.

## External effects

Local release candidates are not production deployments. Idempotency prevents known duplicates inside UNTIL, but cannot undo an external effect or guarantee exactly-once behavior at a provider without provider-side deduplication or reconciliation. A provider receipt is an assertion, not independent physical evidence.

Production deployment, payments, bulk outreach, IAM, destructive operations and irreversible changes require a separately reviewed risk boundary and, where applicable, legally required human authorization.

## Supported version

Security fixes are applied to the current `main` branch and the latest tagged release. Version 0.1 is an engineering MVP; perform your own threat model and paired validation before operational reliance.
